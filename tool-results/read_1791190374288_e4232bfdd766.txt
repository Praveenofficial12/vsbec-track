     1→     1→Build a complete production-ready full-stack web application called:
     2→     2→
     3→     3→"VSBEC Placement Management System"
     4→     4→
     5→     5→The application is designed for a college placement/training department to manage students, company placement drives, attendance, rounds, selections, rejections, and placement analytics.
     6→     6→
     7→     7→The main objective is:
     8→     8→
     9→     9→1. Collect and maintain complete student placement profiles.
    10→    10→2. Allow students to register and maintain their academic/skill information.
    11→    11→3. Allow Admin/Staff to create and manage multiple company placement drives.
    12→    12→4. Track which students attended each company drive.
    13→    13→5. Track students through every recruitment round.
    14→    14→6. Update whether students are selected, rejected, on hold, or still in progress.
    15→    15→7. Provide powerful department-wise, year-wise, class-wise and company-wise analytics.
    16→    16→8. Help placement staff identify suitable students for upcoming companies.
    17→    17→9. Keep all student and placement data centralized and easy to analyze.
    18→    18→10. Make the system simple enough that staff can manage everything without technical knowledge.
    19→    19→
    20→    20→Use a modern, professional, responsive UI suitable for a college placement department.
    21→    21→
    22→    22→Recommended technology stack:
    23→    23→
    24→    24→Frontend:
    25→    25→- React.js
    26→    26→- TypeScript
    27→    27→- Tailwind CSS
    28→    28→- Modern component-based architecture
    29→    29→- Responsive design
    30→    30→- Clean dashboard UI
    31→    31→- Cards, tables, charts, filters and modals
    32→    32→
    33→    33→Backend:
    34→    34→- Supabase
    35→    35→- Supabase PostgreSQL
    36→    36→- Supabase Authentication
    37→    37→- Supabase Row Level Security
    38→    38→- Supabase Storage where required
    39→    39→
    40→    40→Use proper authentication and authorization.
    41→    41→
    42→    42→IMPORTANT:
    43→    43→Do not create a fake frontend-only application.
    44→    44→All important data must be stored in the database.
    45→    45→All student, company, drive, attendance, round and result information must persist after refresh/login/logout.
